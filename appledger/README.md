# AppLedger orientation

This ledger is the project record for the AppLedger repository. It is not the normative specification. Read `spec/README.md` for the format.

AppLedger is a text record of what an application is for, how it fits together, what it does, and how it changes. This repository holds that specification, a format checker, and this ledger about the product itself.

Current phase: Plan. Subject discovery is read-only. AppFacts 0.1.0, FeatureFacts 0.2.0, SkillFacts 0.1.0, ToolFacts 0.1.0, AgentFacts 0.1.0, and ModelFacts 0.1.0 schemas are pinned. A FeatureFacts refresh may set a derived capability title without copying recognition or lifecycle. SkillFacts propose does not rewrite a label: keyword guesses stay drafts, and a bundled script is read rather than executed. ToolFacts propose compares a recorded tools/list and does not start an MCP server or rewrite the label. AgentFacts propose checks a configuration against tool reach, keeps its identity when the toolset changes, and does not claim host enforcement. ModelFacts propose reads offline metadata and does not contact a provider or copy one variant's context window or benchmarks onto another. `render --view public` omits internal records and does not upload or deploy. The accepted name is `appledger` for the GitHub repository, the npm package, the CLI, and this directory. npm `0.0.0` is a name hold, not a release of this source.

The checker does not migrate ForgeTrail. `.forgetrail/workflow_tracking.json` is a pointer, not a second decision log. AppLedger.dev is not deployed. No xFacts labels are claimed.
